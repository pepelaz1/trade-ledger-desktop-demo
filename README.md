# Журнал сделок · прототип для Windows

Локальное настольное приложение для просмотра результатов сделок Bybit. Без аккаунта и API-ключей открывает отдельную SQLite-базу с тестовыми операциями. Исходники и демонстрационные данные доступны для проверки.

## Запуск

Нужен Python 3.10+ на Windows 11.

```powershell
py -m pip install -r requirements.txt
py app.py
```

Готовую Windows-сборку можно взять в [Releases](https://github.com/pepelaz1/trade-ledger-desktop-demo/releases). Распакуйте архив целиком и запустите `TradeLedger.exe` двойным кликом. Папку `_internal` нужно оставить рядом с `.exe`; Python для запуска сборки не требуется.

Сборка из исходников:

```powershell
py -m pip install -r requirements-build.txt
py -m PyInstaller --noconfirm --onedir --windowed --name TradeLedger app.py
```

Результат появится в `dist/TradeLedger/`. Проверен запуск именно этой папочной сборки. Однофайловая сборка в ограниченной рабочей среде не смогла распаковать DLL во временную папку; поэтому в релиз включён проверенный папочный вариант.

Интерфейс прототипа сделан на встроенном Tkinter. Пакет `openpyxl` нужен только для экспорта XLSX. При первом запуске создаётся `data/demo.sqlite`; перед каждым следующим открытием её копия сохраняется с отметкой времени в `data/backups/`.

## Что реализовано

- Тёмная панель с пятью показателями, прогрессом годового порога, календарём и фильтром операций по дням.
- Светлый фон вокруг тёмных панелей и переключатель из 10 установленных шрифтов; по умолчанию выбран Corbel.

- Локальная SQLite, резервная копия при запуске и защита от повторной вставки операций.
- Перевод времени операции в дату по Москве; сальдирование прибылей и убытков внутри года; демонстрационный расчёт резерва 13%/15% с новым годовым порогом 2 400 000 ₽. Бонусы включаются отдельным переключателем.
- Календарь показывает результат по дням; CSV в UTF-8 с BOM и разделителем `;`; XLSX с двумя листами, сводкой и формулами.
- Отдельный клиент официального Bybit V5: подписанные GET-запросы, окна по шесть дней и постраничная загрузка по cursor.
- Запрос исторического USD/RUB через XML Банка России с локальным кэшем по дате в SQLite.

В списке шрифтов: Bahnschrift, Calibri, Candara, Century Gothic, Corbel, Franklin Gothic Medium, Tahoma, Trebuchet MS, Verdana и Georgia. Выбор меняет интерфейс сразу, без перезапуска.

## Необязательный импорт из Bybit

Создайте ключ Bybit **только для чтения** с минимальными правами на историю операций. Ключи задаются через переменные окружения и не сохраняются приложением.

```powershell
$env:BYBIT_API_KEY = '...'
$env:BYBIT_API_SECRET = '...'
py import_bybit.py --from-day 2026-11-01 --to-day 2026-11-07
```

Экспериментальная команда загружает закрытый P&L линейных контрактов в `data/live.sqlite`. На реальном аккаунте она пока не проверялась. Основное окно намеренно открывает изолированную демонстрационную базу. Клиент `transaction-log` поддерживает постраничную загрузку, но его поля ещё нужно сопоставить с конкретными операциями на реальном образце. Торговых запросов и вывода средств в коде нет.

## Что требуется до рабочей версии

После получения подробного ТЗ прототип дополнен годовым сальдированием, кэшем курса, дневными суммами календаря и русским Excel-регистром. До приёмки по ТЗ остаются: интерфейс на CustomTkinter/PySide6, вкладка настроек и безопасное хранение параметров, классификация полного журнала `transaction-log`, сверка с фактическим балансом UTA, расчёт доступного вывода, полная тестовая симуляция, дополнительные вкладки и фильтры, а также тесты с ключом основного и субаккаунта. Полный DOCX не публикуется в репозитории.

Налоговый резерв демонстрационный и требует проверки методики на реальных операциях. Карточки сверки и безопасного вывода честно показывают отсутствие данных UTA вместо выдуманного значения.
